# WHAB

WHAB uses Python, FastAPI and Jinja with bundled SQLite storage and Plaid bank plugins. Read README.md for setup and current limitations.

- Support Python 3.14 and newer only. Keep package requirements, Ruff, CI, setup instructions, and pending branch-protection check names aligned; do not add compatibility code or CI for older Python versions.
- Keep monetary values in integer USD cents. Preserve demo/personal and Sandbox/production isolation.
- Never print, commit, or send `.env` contents, Plaid secrets, access tokens, or private data files. Configure credentials locally.
- Default to Sandbox. Production Item creation consumes a cumulative Trial allowance; avoid duplicate connections. Use Link update mode for existing connections.
- Store Plaid tokens encrypted on the server. Do not expose them to browser code or browser storage, exports, logs, or API errors.
- Save transaction changes and synchronization cursors atomically. Preserve user annotations through matched pending-to-posted transitions.
- Imported history before `budgetStartMonth` is analytics data, not envelope debt. Avoid adding imported income to account balance snapshots.
- This prototype is local only. Shared family access requires authentication and authorization before network deployment.
- For substantive changes, update relevant README behavior or limitations and run `.venv/bin/python -m pytest` and `.venv/bin/python -m ruff check src scripts tests plugins conftest.py`. Browser checks should use demo or Sandbox data.
- Keep domain rules independent of web, interfaces, databases, providers and plugin runtimes. Use the public `whab.plugins` SDK for external extensions; do not add plugin imports to core rules. See CONTRIBUTING.md and docs/architecture.md.
- Treat storage as a selected plugin: `WHAB_STORAGE=sqlite` is the default required backend, loaded alongside optional `WHAB_PLUGINS`. A blank optional list disables optional extensions but keeps storage. Core app/web/plugin-runtime code must not import concrete storage or bank implementations; use SDK protocols and the generic bank facade.
- Storage factories own backend paths and compatible migrations. Preserve legacy SQLite filenames in its plugin, retain transactional ledger/cursor guarantees, and never silently fall back or automatically migrate data when changing backends. Close owned resources on startup failure and shutdown; tests own injected backends.
- Treat visuals as a selected UI plugin: `WHAB_UI=web` is the bundled default, `WHAB_UI=` is headless with APIs/storage. Keep views, templates and browser assets in the UI plugin; core app/web transport must not import concrete interfaces or build visual/business logic. API v1 supports server-rendered web interfaces, not arbitrary native UI runtimes. Descriptor kinds are user_interface, storage, data_ingestion, reporting and branding. Optional bank logos receive institution text only; keep their remote fetches separate from page rendering and banking credentials.
- Package templates/static files with the application. Keep runtime `.env`/data paths independent of code paths and run `.venv/bin/python scripts/check_distribution.py` for packaging or plugin changes.
- Keep each concrete plugin's implementation, assets, docs and tests in `plugins/<id>/`; keep shared SDK/host contracts in `tests/`. Run checks from this application directory. See plugins/README.md for folder ownership and packaging registration.
- Require 100% Python statement and branch coverage for every plugin. Run `.venv/bin/python scripts/check_plugin_coverage.py` before submitting; do not suppress runtime gaps with exclusions or pragmas. Keep coverage regressions in the owning plugin's tests.
- Keep browser JavaScript small; business logic and page rendering belong in Python. No Node build or React runtime is required.
- Keep private files and generated assets out of Git; stage source files explicitly.
- Preserve legacy SQLite filenames, the opaque Plaid household identity, and browser OAuth storage keys through renames. The app package and command are only `whab`; do not reintroduce an `ihab` launch alias. WHAB's version source is `src/whab/__init__.py`.
- Use a feature branch and a pull request for every change to `main`; never push commits directly to `main`. Squash merge after reviewing the final diff and passing CI. The sole maintainer has authorized routine WHAB PR review and merging without another confirmation; fix failing checks or substantive review findings first. GitHub cannot approve a PR using its author's account, so no second-person approval is required.
- Follow SemVer from `1.0.0`: patch for compatible fixes/maintenance, minor for compatible features, major for breaking the documented compatibility contract. Every material change, including runtime or dependency support changes, must bump `src/whab/__init__.py::__version__` and add a dated CHANGELOG.md entry in the same PR. Verify packaging, CLI, FastAPI, and About versions match before merging. Create an immutable `vX.Y.Z` tag and GitHub release on the merged commit only when the user explicitly requests a release; version bumps do not require releases. Small documentation-only changes may wait for the next version bump. See CONTRIBUTING.md for the compatibility contract and current branch-protection status.
