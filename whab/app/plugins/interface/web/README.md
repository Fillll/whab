# Web interface plugin

Distributed independently as `whab-web-plugin`. Its version and dependency compatibility range are defined in [pyproject.toml](pyproject.toml); its dated history belongs in [CHANGELOG.md](CHANGELOG.md). Material changes confined to this plugin update its version and changelog, without an app version or app changelog change.

`src/whab_web/` owns the bundled visual descriptor, view models, icons, Jinja templates and browser assets. Keep rendering and presentation tests alongside them in this folder. The host owns HTTPS routes and access guards through the public UI contract. Every request requires TLS; ordinary visual/private routes remain loopback-only, with only bearer-authorized remote protocol and verified bank-webhook routes exempt from local Host/origin checks.

Templates and static files must ship in the wheel. Use demo data for browser checks and preserve escaping and visual fallbacks.

Browser views use `/budgets/<budget-key>/<page>/<month>/<currency>`; every path segment is lowercase. The original budget is `home`, named budgets use their permanent IDs, and the single sample budget is `demo`. Display names do not determine keys. Pages are `budget`, `transactions`, `insights` and `accounts`. `current-month` follows the calendar on each load; an explicit `2026-10` stays fixed. Page and currency links preserve the month token, while month arrows select an explicit month. Category selections may use query parameters. The root opens the initial demo or selected saved budget; an explicit `--budget` or `WHAB_BUDGET` launch opens its permanent-ID address without a cookie and starts only that selected runtime. `home` is available on ordinary local launches, and demo uses the startup runtime's sample data. Old query-style view addresses are not supported. See [budget addresses](../../../../docs/usage.md#budget-addresses).

The host scopes page context, API requests, plugin assets and downloads by the address's budget so another tab's selected-budget cookie cannot redirect an operation. Browser scripts retain uppercase ISO currencies in API payloads. These routing inputs and targeted downloads require WHAB 2.6 or newer.

The budget workspace offers Light and Dark appearances with the compass logo's red and yellow accents. Light uses warm neutral surfaces; Dark uses charcoal surfaces. Three consecutive months align over one category table. Each month shows its core-calculated **To assign**, **Assigned**, **Spent** and **Available** summary, with **Assigned**, **Activity** and **Available** columns below. The month strip moves the visible window; category groups collapse together across months. Select a category to open its details, or edit its assigned amount directly in the appropriate month. Assignments before the budget start month remain disabled, and every save goes through core validation, including future funding limits. Settings remains anchored at the bottom left on desktop and mobile.

The descriptor requests `budget_months=3` from WHAB 2.2 or newer. The host supplies selected-currency public projections in `data['periods']`; the plugin only arranges and formats them. Rollover, spending, card reserves, available money and funding rules are not calculated in browser JavaScript or duplicated in the skin. Storage plugins continue to implement the existing single-month query contract.

Transactions display merchant artwork supplied by the enabled Plaid plugin through a local image route. The payee name and notes remain visible; artwork loads independently and falls back to the merchant's initial on failure. Transactions without supplied artwork keep their text-only presentation.

Accounts and the sidebar separate **On-budget** everyday accounts from **Off-budget** assets and debts. On-budget checking, savings and credit accounts participate in budget income and spending. Off-budget investments, retirement accounts, property, loans and deposits (including CDs) contribute to net worth while their transactions remain available for review. Assets, liabilities and net worth use current known balances in the selected currency; stale and unavailable snapshots are excluded. Currencies are never combined.

**Add manual account** offers budget scope, account type and relevant account details, such as brokerage, Roth IRA, 401(k), home, mortgage or CD. Enter liabilities as the positive amount owed. **Edit classification** changes an existing account's scope, type and detail; its scope applies to every transaction in that account and updates budget totals accordingly.

From the application directory, run `.venv/bin/python -m pytest plugins/interface/web/tests`. See [plugin contribution rules](../../README.md) for all checks and packaging.

Settings contains **Budgets**, **Plugins**, and **About this prototype**. Budgets lists every budget in the host catalog alongside the single **Demo budget** destination, with a radio selection, one **Current budget** marker, and a separate **Download** button on each row. Downloading preserves the selected budget; a demo download contains only fictional data and opens as a fresh budget. Enter a password if needed, then choose the red **Open selected budget** button to switch. **Create new budget** and **Open existing budget** follow in separate sections, with a name field or portable-file/password/separate-budget controls. The red **Create budget** and **Open budget** actions leave Settings only after success; failures keep the dialog and entered information. Switching budgets preserves the page, month and currency while clearing the previous category selection. Saved-copy synchronization and encrypted remote-credential exports remain under **Saved copies and export options**. The core owns budget creation, persistence, isolation and downloads; this plugin owns presentation and navigation. The same controls work on desktop and mobile.

Open **Settings → Plugins → Installed** to select plugins. The category filter starts with **All categories**, with alphabetical category sections and plugin names. Example plugins are hidden, and valid existing example selections survive saving other choices. Required storage and interface plugins stay selected. Saving an optional selection applies it on the next restart and preserves the running plugins until then.

Every visible installed-plugin row has an **Options** page; hidden teaching examples have no ordinary Settings row or Options page. Each visible page includes its category, version, saved selection and running state. Running plugins can expose generic settings information and actions through the public SDK; inactive plugins show enable/restart guidance without running their hooks. Settings values and action feedback render as text. The bank-logo plugin uses this page for its one-year cache policy and **Flush cache** action.

**Download** keeps credentials on the device. The additional export form can explicitly include a password-encrypted remote access credential. Only that credential is encrypted; the rest of the container remains readable plugin data, and bank-provider tokens are never included. Upload and saved-budget switching accept an optional password without placing it in URLs or browser storage.

Choose **Settings → Plugins → Installed → WHAB web → Options → Appearance**, then **Light** or **Dark**. The change applies immediately across the web interface. The preference is remembered in this browser for the current origin (hostname and port), independently of financial data and portable budget settings. With no saved choice, the initial appearance follows the browser's system preference. When browser storage is unavailable, switching still works for the current page. The appearance script restores a saved choice before the stylesheet loads; web assets use the web plugin's version so plugin-only updates refresh their styling.
