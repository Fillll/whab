# Web interface plugin

Distributed independently as `whab_plugin_web`. Its version and dependency compatibility range are defined in [pyproject.toml](pyproject.toml); its dated history belongs in [CHANGELOG.md](CHANGELOG.md). Material changes confined to this plugin update its version and changelog, without an app version or app changelog change.

`src/whab_plugin_web/` owns the bundled visual descriptor, view models, icons, Jinja templates and browser assets. Keep rendering and presentation tests alongside them in this folder. The host owns HTTPS routes and access guards through the public UI contract. Every request requires TLS; ordinary visual/private routes remain loopback-only, with only bearer-authorized remote protocol and verified bank-webhook routes exempt from local Host/origin checks.

Templates and static files must ship in the wheel. Use demo data for browser checks and preserve escaping and visual fallbacks.

The sidebar footer shows a green status dot and the running WHAB application's version, using the host version supplied with the page. An icon-only Settings button sits at the far right of the same row, with a Settings tooltip and accessible name. Compact screens retain the Settings button while hiding the status dot and version.

Browser views use `/budgets/<budget-slug>/<page>/<month>/<currency>`; account registers use `/budgets/<budget-slug>/<account-slug>/transactions/<month>/<currency>`. Names become lowercase, hyphenated aliases with accented Latin normalization and Cyrillic transliteration. Duplicate names get numeric suffixes, and old aliases remain valid after renames through a device-local registry. Permanent IDs still scope API calls/assets; old UUID, `home` and `?account=<id>` links continue to work. The single sample budget remains `demo`. Pages are `budget`, `transactions`, `insights` and `accounts`. `current-month` follows the calendar on each load; an explicit `2026-10` stays fixed. Page and currency links preserve the month token; month arrows select an explicit month. Category selections may use query parameters. The root opens the initial demo or selected saved budget; an explicit `--budget` or `WHAB_BUDGET` launch starts only that selected runtime and opens its readable address. `home` remains available on ordinary local launches, and demo uses the startup runtime's sample data. Old root query-style view addresses are not supported. See [budget addresses](../../../../docs/usage.md#budget-addresses).

The host scopes page context, API requests, plugin assets and downloads by the address's budget so another tab's selected-budget cookie cannot redirect an operation. Browser scripts retain uppercase ISO currencies in API payloads. These routing inputs and targeted downloads require WHAB 2.6 or newer.

The budget workspace offers Light and Dark appearances with the compass logo's red and yellow accents. Compact month cards align over three months of **Income**, **Carried in**, **Assigned for next month**, **Assigned this month** and **Available to assign**, with one amount per row and month. Carried in is explicitly labeled as previously unassigned money, money set aside for this month, and overall category carryover. Its expandable breakdown uses core's existing component amounts; category-mode balances remain exclusively in the category Carryover columns. Assigned for next month is an independent transfer out of this month's assignable pool and into next month's carry-in; it can be below next month's category assignments. Plain values and Summary labels distinguish read-only totals from outlined editable amounts. Detailed Carryover, Assigned, Activity and Available headings appear within Spending categories, with sticky labels, parent summaries and editable child assignments. Settings remains at the bottom left.

Every read-only amount in the overview has a native **Where it comes from** disclosure for its own month. Income explains received money and links to that month's transactions; historical income before the budget starts is identified as history. Assigned this month points to the matching Assigned total at the bottom of the spending table. **Show matching total** focuses that total and highlights both matching values without repeating every category. Available to assign shows Income plus Carried in minus Assigned for next month minus Assigned this month, using core's actual component values and signed result. Carried in retains its component breakdown. Editable next-month funding stays an input; a valid read-only fallback explains the saved set-aside. Unavailable amounts never receive a fabricated explanation. Disclosures work with the keyboard and retain the selected currency's precision.

Budget assignments and rollover choices save in place, with local saving, saved and error feedback. Edits are serialized without locking unrelated fields. After a validated save, a small server-rendered budget fragment updates only changed DOM values; the active field, newer drafts, scroll position, expanded explanations and collapsed groups stay in place. Python remains the authority for all amounts. The fragment is requested at the same budget address with `X-WHAB-Budget-Fragment: 1` and uses the same HTTPS, budget scoping and no-store protections as the full page. It contains the budget planner without the navigation shell or dialogs. The bottom of the table retains Add category without repeated currency or planning notes.

The descriptor requests `budget_months=3` and requires WHAB 2.9 or newer. The host supplies selected-currency public projections in `data['periods']`; the plugin formats core's `summary.carriedIn`, `carriedInUnassigned`, `carriedInSetAside`, `balanceCarryover`, `assignedNextMonth`, `assigned` and `readyToAssign`. Core advertises `monthlyFundingFlow: true`; the UI requires that exact capability together with `nextMonthFundingEditable: true` before editing independent next-month set-asides. Until an older remote server is upgraded, Carried in, Assigned for next month and Available to assign display dashes, and next-month editing is unavailable. Missing or invalid totals also display dashes. No next-month editor appears before the budget starts or at `2200-12`. Saving sends the displayed source month, currency and amount to `PUT /api/budget/funding/next-month`. If core's conservative `fundingCapacity` is below the monthly pool total, a note inside **Where it comes from** explains that spending or account reserves limit new assignments. Budget rules remain in core.

Each month's **Carryover** radio group offers **By category** and **Overall balance**, followed by **Into <next month>**. The first carries category surpluses and deficits individually; the second resets incoming category balances and exposes their signed net in **Carried in**, already included in general cash. The control saves the displayed source month and currency to `PUT /api/budget/settings/rollover`, and uses the per-currency `rolloverMode` and literal `rolloverModeEditable: true` capability. Older servers, pre-budget months and the final supported month remain read-only. Editing an earlier rule recalculates subsequent months. A receiving month whose `incomingRolloverMode` is `category` shows a read-only **Carryover** column before Assigned, including positive, zero and negative amounts and calculated group and monthly totals. The previous month's rule controls this column even when that month is outside the displayed window. The first budget month and months receiving an overall balance use the three-column layout. Available amount tooltips also show carried-over, assigned and activity values.

The compact transaction table has independent multi-select checkboxes, Date, Receipt, Payee, Category, Memo, signed Amount, Currency and a small **R** reviewed toggle. Pending transactions cannot be reviewed. Category, memo and review edits save in place, with serialized writes and retry feedback. Sidebar account changes fetch only the main register, preserve sidebar scroll and support Back/Forward. Outstanding edits finish before navigation.

Receipt images are optional storage-owned attachments, available with SQLite: JPEG, PNG or WebP up to 5 MiB and 25 megapixels each. Save, open or remove an image from the Receipt column. They stay with the budget across restart and portable export; a storage plugin without attachment support leaves the control unavailable. Receipts are private budget data and never sent to a bank or artwork provider.

Transactions display merchant artwork supplied by the enabled Plaid plugin through a local image route. The payee name and editable memo remain visible; artwork loads independently and falls back to the merchant's initial on failure. Transactions without supplied artwork keep their text-only presentation.

Accounts and the sidebar separate **On-budget** everyday accounts from **Off-budget** assets and debts. On-budget checking, savings and credit accounts participate in budget income and spending. Off-budget investments, retirement accounts, property, loans and deposits (including CDs) contribute to net worth while their transactions remain available for review. Assets, liabilities and net worth use current known balances in the selected currency; stale and unavailable snapshots are excluded. Currencies are never combined.

Choose an individual sidebar account to open its transactions with **All dates** selected. The account selector and heading identify the register; turn off All dates to use the month field. The main **Accounts** navigation opens account management. Account and date filters remain in the address, and switching currency clears the account selection.

**Add manual account** offers budget scope, account type and relevant account details, such as brokerage, Roth IRA, 401(k), home, mortgage or CD. Enter liabilities as the positive amount owed. **Account settings** in an individual register changes the account name, scope, type and detail. Scope applies to every transaction in that account and updates budget totals accordingly. Currency can change only before any transaction history exists, including deleted history. Names survive bank refreshes. When Bank logos is active, Account logo accepts a public HTTPS bank website, identifies the plugin and its Options, and explains that only the domain goes to Icon Horse (`icon.horse`).

From the application directory, run `.venv/bin/python -m pytest plugins/interface/web/tests`. See [plugin contribution rules](../../README.md) for all checks and packaging.

Settings contains **Budgets**, **Plugins**, and **About this prototype**. The Budgets dialog has three titled sections. **Open budget** lists every budget in the host catalog alongside the single **Demo budget** destination, with a radio selection, one **Current budget** marker, and a separate **Download** button on each row. Downloading preserves the selected budget; a demo download contains only fictional data and opens as a fresh budget. Enter a password if needed, then choose the red **Open selected budget** button to switch. **Create new budget** contains the name field and **Create budget** action. **Add budget** contains a WHAB file chooser, an optional password and **Add as a separate budget**. Its **Add budget** action adds the file to the catalog and opens it. All three actions leave Settings only after success; failures keep the dialog and entered information. Switching budgets preserves the page, month and currency while clearing the previous category selection. Saved-copy synchronization and encrypted remote-credential exports remain under **Saved copies and export options**. The core owns budget creation, persistence, isolation and downloads; this plugin owns presentation and navigation. The same controls work on desktop and mobile.

Open **Settings → Plugins → Installed** to select plugins. The category filter starts with **All categories**, with alphabetical category sections and plugin names. Example plugins are hidden, and valid existing example selections survive saving other choices. Required storage and interface plugins stay selected. Saving an optional selection applies it on the next restart and preserves the running plugins until then.

Every visible installed-plugin row has an **Options** page; hidden teaching examples have no ordinary Settings row or Options page. Each visible page includes its category, version, saved selection and running state. Running plugins can expose generic settings information and actions through the public SDK; inactive plugins show enable/restart guidance without running their hooks. Settings values and action feedback render as text. The bank-logo plugin uses this page for its one-year cache policy and **Flush cache** action.

Enabled file importers render their upload form in **Options**, from every page including Demo. **Import from YNAB ZIP file → Options** explains that **Create budget and import** creates and opens a separate budget after preview; the Accounts management page contains no import panel. Dropdowns share inset, centered chevrons while retaining native keyboard and high-contrast behavior.

**Download** keeps credentials on the device. The additional export form can explicitly include a password-encrypted remote access credential. Only that credential is encrypted; the rest of the container remains readable plugin data, and bank-provider tokens are never included. Upload and saved-budget switching accept an optional password without placing it in URLs or browser storage.

Choose **Settings → Plugins → Installed → WHAB web → Options → Appearance**, then **Light** or **Dark**. The change applies immediately across the web interface. The preference is remembered in this browser for the current origin (hostname and port), independently of financial data and portable budget settings. With no saved choice, the initial appearance follows the browser's system preference. When browser storage is unavailable, switching still works for the current page. The appearance script restores a saved choice before the stylesheet loads; web assets use the web plugin's version so plugin-only updates refresh their styling.
