# Subscriptions

An optional Automation plugin that labels transactions as subscription or not, independently of budget categories and transaction review. Enable **AI credentials** and **Subscriptions**, restart when requested, then choose **Subscriptions** in the main sidebar. It can run alongside either budget categorizer. Requires WHAB 2.50+, Python 3.14+, and `whab_plugin_ai_credentials>=1.0.0,<2`.

The view shows recent plans, estimated monthly/annual costs, the largest categories and merchants, twelve months of actual classified charges and month-to-month increases. Select the currency and month in the main workspace before opening it. Currencies are never combined. Actual charges include historical subscriptions; estimates include only plans with a recent charge. A missing recent charge is not confirmation of cancellation.

Connect a provider under **Settings → Plugins → AI credentials**. In the subscription view, open **AI classification settings**, select a provider, model and effort, review the data permission and choose **Save and classify unchecked transactions**. Classification visits the full history, including already reviewed and categorized records, in requests of at most 20 payment patterns. Progress saves after every successful batch. Classification runs on the budget host in a background job. Closing the view or browser tab leaves the job running while WHAB stays open. Reopen Subscriptions to see the saved progress. The progress bar shows checked/total transaction counts, reused decisions and changed/deleted payments skipped during the scan. **Stop classification** stops after the current batch finishes; its completed results remain saved. Starting again checks only the remaining unchecked transactions. New imports remain unchecked until **Classify unchecked transactions** is chosen again. No paid inference runs on ordinary page reads or bank imports.

## Classification and caching

Pending payments, transfers and nonpositive amounts receive an excluded label; every other transaction is eligible. The classifier distinguishes ongoing subscriptions and memberships from ordinary shopping, rent, utilities, loans and income. Recurrence alone does not prove a subscription. AI scores below 0.8 remain **Needs review** and are excluded from costs. Unknown billing intervals are shown without an invented monthly equivalent.

Labels persist in the budget's `subscriptions.json` namespace, with separate demo files. A fingerprint invalidates a label after merchant, amount, date, currency or account changes. Category/note edits do not cause another AI call. Matching merchant (case/whitespace normalized), amount, currency, account and billing day reuse positive or negative saved decisions. Dates 28–31 share a month-end anchor. The same match is classified together in the first request; recurrence dates are supplied as evidence. Changing provider/model/effort/connection invalidates AI caches; manual corrections survive. Unknown/low-score results stay visible for review rather than being repeatedly charged to AI.

Under **Review payments**, select subscription charges, uncertain payments, unchecked payments or all transactions, and search by merchant/category. Choose a label and billing interval, then **Save label**. This explicitly corrects every matching payment in the account. Manual labels outrank AI results and apply to future matching payments. Stale transactions must be refreshed before a correction. No categories, review flags, account balances or bank records change.

Monthly estimates use integer minor units, rounding half up: monthly charge, annual / 12, quarterly / 3, weekly × 52 / 12. Price changes use the latest charge rather than counting the former price as another plan. Charges for the same merchant/account/billing day are combined for reporting; distinct plans with those exact details need manual review. Duplicate charges on the latest billing date are counted together. A monthly/unknown plan is recent within 62 days, annual within 400, quarterly within 110 and weekly within 16, relative to the selected month end or today, whichever is earlier. These are estimates, not forecasts or cancellation detection. Historical payments are never removed from actual-cost charts.

## Data and ownership

AI receives bounded payee names, amounts, currencies, billing days, occurrence counts and up to 24 observed months, with request-local transaction numbers. Account IDs, full transaction dates, notes, categories, balances, receipts and bank credentials are excluded. Model responses are strictly validated before a batch is saved. Each result is revalidated against the current transaction fingerprint before saving. Materially edited, deleted, pending or newly transferred transactions are skipped; note/category changes do not discard valid results. New imports wait for the next explicit scan. Successful earlier batches survive a later provider or persistence error. The plugin uses sanitized coherent portable ledger snapshots and its own namespaced files through public SDK contracts. AI requests go through the credentials plugin's documented public API; no private cross-plugin imports or state access.

The plugin owns classification, caching, corrections and report arithmetic. Web owns the sidebar button, review dialog and display. The host only supplies local settings namespaces. This local transport keeps existing HTTPS/Host/origin guards; it introduces no remote protocol operation or new financial fields. Disabling the plugin retains its saved state.

Run `.venv/bin/python -m pytest plugins/automation/subscriptions/tests` from `whab/app/`. Tests use fictional records and mocked providers.

## Background jobs

From version 1.1, the local settings transport also accepts `start` with a UUID `operationId` and optional configuration, `job` for lightweight progress reads, and `stop` with the observed `jobId`. Existing status/configure/override and the legacy single-batch `classify` action remain compatible. Status includes the current `job`. Starting an active job again attaches to it; repeating the same completed operation ID returns its original receipt. A stale Stop cannot cancel a newer job. Settings, label corrections and legacy batch requests are refused while background work is active; ordinary ledger reads/edits remain available.

Progress metadata lives in `classification-job.json`, separately for personal/demo and each budget. It contains only a job UUID, state, counters, timestamps, configuration digest and authored errors. It contains no transactions or credentials. The queue is fixed at Start, and valid cached peers may supply evidence. Only the server advances batches; browser polling cannot duplicate inference.

WHAB shutdown requests a stop after the current batch, waiting at most 50 seconds. A result arriving after retirement cannot access the budget or write labels. Unfinished saved jobs reopen as **Interrupted**, without automatically retrying a provider request. Choose **Classify unchecked transactions** to continue deliberately; completed labels are reused. The progress receipt may lag a completed label save after an interrupted write, so the next scan derives its remaining work from the labels themselves. No automatic retries, paid page reads or bank-import inference are introduced.
