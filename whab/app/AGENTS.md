# WHAB

WHAB uses Python, FastAPI and Jinja with independently packaged SQLite storage and Plaid bank plugins in its supported default set. Read README.md for setup and current limitations.

- Support Python 3.14 and newer only. Keep package requirements, Ruff, CI, setup instructions, and branch-protection check names aligned; do not add compatibility code or CI for older Python versions.
- Keep monetary values in integer currency minor units (USD cents). Never aggregate or convert unlike currencies; accounts and child categories declare currency, and each transaction inherits its account currency. Preserve demo/personal and Sandbox/production isolation.
- Never print, commit, or send `.env` contents, Plaid secrets, access tokens, or private data files. Configure credentials locally.
- Default to Sandbox. Production Item creation consumes a cumulative Trial allowance; avoid duplicate connections. Use Link update mode for existing connections.
- Store Plaid tokens encrypted on the server. Do not expose them to browser code or browser storage, exports, logs, or API errors.
- Save transaction changes and synchronization cursors atomically. Preserve user annotations through matched pending-to-posted transitions.
- Imported history before `budgetStartMonth` is analytics data, not envelope debt. Avoid adding imported income to account balance snapshots.
- Require HTTPS on every route, including localhost, remote operations and webhooks; never add HTTP fallback or trusted proxy-header bypass. Keep the visual app and private banking routes on localhost with Host/origin checks. Only explicitly enabled server `/remote/v1` operations and registered signed bank webhooks bypass those local checks; remote operations require budget-scoped bearer authorization and webhooks require provider signature verification. TLS encryption is separate from those authentication checks. Never expose bank tokens, private storage methods or local management endpoints remotely. Local CA trust changes require explicit user action; setup must not modify OS trust.
- For substantive changes, update relevant README behavior or limitations and run `.venv/bin/python -m pytest` and `.venv/bin/python -m ruff check src scripts tests plugins conftest.py`. Browser checks should use demo or Sandbox data.
- Keep domain rules independent of web, interfaces, databases, providers and plugin runtimes. Use the public `whab.plugins` SDK for external extensions; do not add plugin imports to core rules. See CONTRIBUTING.md and ../docs/architecture.md.
- Treat storage as a selected plugin: `WHAB_STORAGE=sqlite` is the default required backend for the original workspace and CLI budget creation; an opened portable budget uses its manifest's storage. Settings creates new SQLite budgets. Required storage loads alongside the budget's available optional plugins; missing portable optional packages retain their data and are reported without blocking opening. A blank effective optional selection disables optional extensions but keeps storage. Core app/web/plugin-runtime code must not import concrete storage or bank implementations; use SDK protocols and the generic bank facade.
- Install executable plugin code per WHAB environment; portable budgets own their enabled plugin IDs, compatible API requirements, public settings, state and namespaced files. Preserve disabled or unavailable plugin data without executing code. Bind budget-specific hooks through the public `BudgetContext`/`Plugin.bind` contracts. Copy paths stay device-local.
- Portable `.whab` containers always have a validated manifest and plugin-owned data-only payloads; SQLite carries a sanitized database and remote storage carries connection information. Read legacy manifest/ledger bundles. Never include Python code, bank Items, provider tokens, cursors or encryption keys. Remote API credentials may be explicitly exported only in a password-encrypted section bound to the budget and remote target; never combine an imported target with unrelated device credentials. Preserve the legacy runtime, isolated storage, recovery journals and conflicting revisions or copy destinations.
- Storage factories own backend paths and compatible migrations. SQLite reopens a single `data/*-{environment}.sqlite` file in place, validating the base schema for a noncanonical filename. Create `data/whab-{environment}.sqlite` only when no matching file exists, and fail when multiple files match, including the canonical filename. Retain transactional ledger/cursor guarantees, and never silently fall back or automatically migrate data when changing backends. Close owned resources on startup failure and shutdown; tests own injected backends.
- Treat visuals as a selected UI plugin: `WHAB_UI=web` is the bundled default, `WHAB_UI=` is headless with APIs/storage. Keep views, templates and browser assets in the UI plugin; core app/web transport must not import concrete interfaces or build visual/business logic. API v1 also supports scoped transport interface factories; the bundled server and client communicate through public ledger commands/queries, with shared locking, revision checks and bounded idempotency receipts. Descriptor kinds are user_interface, storage, data_ingestion, reporting and branding. Optional bank logos receive institution text only; keep their remote fetches separate from page rendering and banking credentials.
- Package each plugin's templates/static files in that plugin's independent distribution. The host/core wheel must not contain concrete plugin packages or their entry points; the bundled extra and source installer supply the seven supported plugins. Each concrete plugin owns its `pyproject.toml` version, entry point and dated `CHANGELOG.md`. Keep runtime `.env`/data paths independent of code paths and run `.venv/bin/python scripts/check_distribution.py` for packaging or plugin changes.
- Keep each concrete plugin's implementation, assets, docs and tests in `plugins/<category>/<id>/`. Categories are singular: `interface`, `ingestion`, `insight`, `storage`, `automation`, `extension` and `example`. Keep IDs lowercase and hyphen-separated, independent of their category; retain existing Python package names. Keep shared SDK/host contracts in `tests/`. Run checks from this application directory. See plugins/README.md for folder ownership and packaging registration.
- Require 100% Python statement and branch coverage for every plugin. Run `.venv/bin/python scripts/check_plugin_coverage.py` before submitting; do not suppress runtime gaps with exclusions or pragmas. Keep coverage regressions in the owning plugin's tests.
- Keep browser JavaScript small; business logic and page rendering belong in Python. No Node build or React runtime is required.
- Browser navigation uses `/budgets/<stable-key>/<page>/<month-or-current-month>/<currency>` with lowercase path values, including currencies. Budget names are display labels, not route identities; `demo` is a separate sample destination with no workspace segment. Keep pages, API calls, downloads and assets bound to the addressed budget independently of cookies.
- Keep private files and generated assets, including runtime `budgets/` and `tls/` material, out of Git; stage source files explicitly. Preserve token encryption keys and TLS private keys securely with their owning runtime home; portable exports omit them.
- Preserve saved ledgers and encrypted Plaid connections by keeping runtime homes and encryption keys together. Use `whab` browser session keys and `whab-local-household` for new Plaid Link tokens; finish in-progress Link flows before upgrading. The app package and command are only `whab`. WHAB's host/core version source is `src/whab/__init__.py`; each plugin version comes from its own `pyproject.toml`.
- Use a feature branch and a pull request for every change to `main`; never push commits directly to `main`. Review the final diff, fix failing checks or substantive review findings, and pass CI before requesting a squash merge. Reserve final approval and merging for the human maintainer @Fillll; agents must not approve or merge a PR unless @Fillll explicitly delegates that action for that specific PR. GitHub does not allow authors to approve their own PRs; @Fillll has a PR-only owner exception for self-authored PRs.
- Follow SemVer from `1.0.0`: patch for compatible fixes/maintenance, minor for compatible features, major for breaking the documented compatibility contract. A material host/core/public-SDK change, including its runtime or dependency support, must bump `src/whab/__init__.py::__version__` and add a dated application `CHANGELOG.md` entry in the same PR. A material plugin-only change bumps only that plugin's `pyproject.toml::project.version` and adds a dated entry to its own `CHANGELOG.md`; it does not require an app version or app changelog change. Changes spanning owners update each affected owner. Verify packaging, CLI, FastAPI, and About versions match before merging. Create an immutable `vX.Y.Z` tag and GitHub release on the merged commit only when the user explicitly requests a release; version bumps do not require releases. Small documentation-only changes may wait for the next version bump. See CONTRIBUTING.md for the compatibility contract and current branch-protection status.
