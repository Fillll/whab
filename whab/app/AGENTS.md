# WHAB application

Run application commands from `whab/app/`. Start with [README.md](README.md), then use the [task ownership map](CONTRIBUTING.md#task-ownership) to read the contracts for the area being changed.

- Support Python 3.14 and newer only. Keep package requirements, tooling and CI aligned. Node is used for browser tests; there is no Node build or React runtime.
- Keep budgeting rules in the financial core, independent of HTTP, storage, providers and concrete plugins. Use the public `whab.plugins` SDK. Follow [code boundaries](CONTRIBUTING.md#code-boundaries) and the [architecture and financial invariants](../docs/architecture.md).
- Use integer currency minor units; never aggregate unlike currencies. Preserve annotations, atomic transaction/cursor saves and saved-data compatibility. Keep demo/personal, Sandbox/production and each budget's plugin state isolated.
- Never print, commit or transmit credentials, bank tokens, private records or encryption/TLS keys. Keep runtime homes separate from source; preserve existing homes and keys across upgrades. Default to Sandbox, avoid duplicate production connections and use Link update mode for existing connections.
- Require HTTPS on every route and retain local Host/origin checks. Only explicitly enabled authenticated remote operations and signed bank webhooks have documented exceptions to local access restrictions. Never trust forwarded headers to bypass TLS, expose bank tokens or change OS certificate trust automatically. Read [security and compatibility contracts](CONTRIBUTING.md#code-boundaries) before changing these paths.
- Before changing storage, portable containers or remote operations, read [budget ownership and compatibility](../docs/target-architecture.md), the [SDK contracts](../docs/plugins.md) and the owning plugin's README. Preserve unavailable plugin data and recovery state; do not silently fall back or migrate between backends.
- Keep each concrete plugin's implementation, assets, tests and version/changelog in its [owning folder](plugins/README.md). Shared host/SDK contracts belong in `tests/`. Plugin Python requires 100% statement and branch coverage; never hide runtime gaps with exclusions or pragmas.
- During iteration use `.venv/bin/python scripts/check_pr.py local --base origin/main` or quick checks plus focused regressions. Required PR CI is authoritative for the complete source suite on Python 3.14/3.15, 100% plugin coverage and installed wheels; do not repeat the exhaustive gate locally before each push. `.venv/bin/python scripts/check.py` remains the exhaustive post-merge/nightly/manual certification, including historical hosts and generated-plugin replays. See [validation](CONTRIBUTING.md#tests-and-checks).
- Use [fictional previews](../docs/development.md#isolated-preview) and the [web acceptance criteria](plugins/interface/web/README.md#ui-acceptance-criteria) for UI work. Verify saved results and follow the [completion checklist](../docs/development.md#completion-and-running-version-verification); distinguish source validation from an installed running change.
- Use a feature branch and PR; stage reviewed source paths explicitly. Honor the [authorization and PR workflow](CONTRIBUTING.md#authorization-and-completion-stages): final approval/merge belongs to @Fillll unless explicitly delegated for the identified PR. Existing authorization carries through that scope. Tags/releases require a separate explicit release request.
- Update the owning behavior documentation, version and dated changelog when required by [SemVer and ownership](CONTRIBUTING.md#pull-requests-and-releases). Every populated changelog section needs its real originating PR links; obtain the URL from a draft PR and follow the [changelog policy](CONTRIBUTING.md#changelog-pr-links).
